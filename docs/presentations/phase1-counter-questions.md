# Phase 1 Review — Anticipated Questions & Responses

| # | Panel Question | Response Strategy |
| --- | --- | --- |
| 1 | **“How do you prevent the agent from running unsafe shell commands?”** | Describe sandboxed adapters (Git, Docker, shell whitelist) and explicit policy in [docs/architecture/AI-DevOps-Commander.md](../architecture/AI-DevOps-Commander.md). No raw shell; only vetted scripts from `infra/scripts`. Mandatory plan preview + approval ensures human-in-the-loop before any adapter call. |
| 2 | **“What happens if the LLM produces a faulty plan?”** | Explain LangGraph chain: CommandInterpreter output is stored as `pending_approval`. RAGAdvisor cross-checks SOP embeddings (Chroma) and flags deviations. Reviewer must approve before execution; WatchdogAgent still monitors runtime to trigger rollback if a bad plan slips through. |
| 3 | **“Why combine local deployments and GitHub Actions? Isn’t one enough?”** | Local-first mode (Git/Docker) enables air-gapped or edge environments. GitHub Actions adapter covers cloud CI/CD parity. Same plan schema fans out to either channel, letting organizations adopt at their own pace. |
| 4 | **“How do you ensure rollback actually restores a known good state?”** | System tracks last-known-good image/tag per service in persistence. Watchdog monitors Prometheus metrics/logs; when thresholds breach, rollback job redeploys that tag and records incident metadata for audit. |
| 5 | **“Chroma is fine for MVP, but what about scale?”** | Architecture already maps to PGVector/Postgres (see Scaling Path section). Embedding repo uses provider-agnostic interface; swapping store is config-level change once Postgres infra is provisioned. |
| 6 | **“What metrics do you monitor to trigger automated rollback?”** | Error rate, latency P95, and exit codes via Prometheus exporters. Thresholds configurable via env vars; WatchdogAgent polls metrics + log digests and fires rollback pipeline if breaches persist for N intervals. |
| 7 | **“How are approvals audited?”** | Plans stored with `status` transitions, reviewer identity, timestamps in SQLite/Postgres. Structured logging uses correlation IDs per plan/execution so audits tie UI actions to backend effects. |
| 8 | **“What’s the roadmap to production readiness?”** | Phase 2: implement FastAPI routers, LangGraph orchestration, adapter hardening. Phase 3: move to Postgres/PGVector, add auth, containerize, enable GitHub Actions adapter for remote deployments, and formalize monitoring dashboards. |
| 9 | **“What if Redis or the worker crashes mid-deployment?”** | Redis + RQ store job state; orchestrator is idempotent. On restart, pending jobs resume; watchdog detects stalled executions and can requeue or alert. Long term, add persistence-backed job leases for stronger guarantees. |
| 10 | **“How will you validate adherence to SOPs beyond embeddings?”** | Combine RAG warnings with policy severity levels. High-severity deviations block approval; medium ones require reviewer justification captured in plan notes. Future work: static rule engine layered atop embeddings for deterministic checks. |
